## 説明

コンポーネントは、関数の引数のように「外から値を受け取る」ことができる。これを**Props(プロパティ)** と呼ぶ。

```tsx
interface GreetingProps {
  name: string;
}

function Greeting({ name }: GreetingProps) {
  return <h1>こんにちは、{name}さん</h1>;
}

// 使う側
<Greeting name="のりまき" />
```

`{ name }: GreetingProps`の部分は、分割代入+型注釈(1章で学んだ組み合わせ)そのもの。JSXで`<Greeting name="のりまき" />`と書くと、`name="のりまき"`という値が1つのオブジェクト(`{ name: "のりまき" }`)としてコンポーネントに渡され、それを分割代入で受け取ってる。

Propsには、文字列や数値だけでなく、**関数を渡すこともできる**。これは「親のコンポーネントが、子のコンポーネントで起きた出来事(ボタンが押された、など)を知りたい」時によく使うパターン:

```tsx
interface ButtonProps {
  label: string;
  onPress: () => void;
}

function MyButton({ label, onPress }: ButtonProps) {
  return <button onClick={onPress}>{label}</button>;
}

// 使う側
<MyButton label="購入する" onPress={() => console.log("押された")} />
```

## 実際のプロトタイプでの例

Cake-Gameの`components/CakeSelector.tsx`から、Propsの型定義と受け取り:

```tsx
interface CakeSelectorProps {
  cakes: CakeDefinition[]
  activeCakeId: CakeKind
  unlockedCakeIds: CakeKind[]
  money: number
  onSelectCake: (cakeId: CakeKind) => void
  onBuyCake: (cakeId: CakeKind) => void
}

export function CakeSelector({
  cakes,
  activeCakeId,
  unlockedCakeIds,
  money,
  onSelectCake,
  onBuyCake,
}: CakeSelectorProps) {
  // ...
}
```

ここで注目してほしいのが、`onSelectCake: (cakeId: CakeKind) => void`という関数の型(1-08で学んだ「関数の型」の応用)。「ケーキが選択されたら、そのケーキのidを引数にして、何かしらの処理をする(戻り値はなし)」という、親コンポーネントに"通知"するための関数をPropsとして受け取ってる。

`cakes: CakeDefinition[]`(前にやったinterfaceの配列)、`activeCakeId: CakeKind`(union type)のように、1章で学んだ型の知識が、Propsの型定義の中でそのまま全部使われてるのが分かるはず。

## コラム:Java・Railsとの対応

### Java

```java
class Greeting {
    private String name;

    public Greeting(String name) {
        this.name = name;
    }
}
```

Javaでの「オブジェクトに値を渡す」といえばコンストラクタが近い。ただしJavaのコンストラクタは「一度だけ値を設定して、そのインスタンスに保存する」という発想だけど、Reactのpropsは「呼ばれるたびに、その時点の値がまるごと渡される」という違いがある(親の値が変わるたびに、子コンポーネントは新しいpropsで再実行される)。

### Rails

RailsのViewComponentを触ったことがあるなら、初期化時に値を渡す書き方がPropsに近い:

```ruby
class GreetingComponent < ViewComponent::Base
  def initialize(name:)
    @name = name
  end
end
```

```erb
<%= render(GreetingComponent.new(name: "のりまき")) %>
```

キーワード引数で値を渡し、コンポーネント内で使う、という構造はPropsとかなり似てる。ただしViewComponentは「一度渡したら固定」のイメージに近く、Reactのように「親の値が変わるたびに自動で再描画される」という発想はない。ここはRailsのリクエスト/レスポンスサイクル(1回のリクエストごとに描画し直す)と、Reactの「画面上で状態が変わり続ける」という前提の違いによるもの。

## 一緒にやってみる

演習に入る前に、Propsの受け渡しを1往復やってみよう。
プロトタイプの`CakeSelectorProps`と同じく、**型を先に定義してから**受け取る形:

```tsx
interface PriceTagProps {
  label: string;
  price: number;
}

function PriceTag({ label, price }: PriceTagProps) {
  return <p>{label}: {price}円</p>;
}
```

このコードを、**コピペせずに自分の手で入力してみてほしい**。書けたら、
`App`から値を渡して表示を確かめ、渡す値を変えると表示も変わることを見てみよう:

```tsx
<PriceTag label="ショートケーキ" price={500} />
```

<TryIt />

書き方の型を整理すると:

```
interface Props名 { プロパティ: 型; }
function コンポーネント名({ プロパティ }: Props名) { ... }
<コンポーネント名 プロパティ={値} />
```

- 受け取り側は`{ }`で**分割代入**して、必要な名前だけ取り出す
- 渡す側は`属性={値}`。文字列だけは`属性="値"`と書ける
- 型を先に決めておくと、渡し忘れ・打ち間違いをその場で気づける

演習では、この形で`ProfileCard`と`ProfileCardProps`を作ることになる。
