## 説明

「ある条件を満たす時だけ、特定のUIを表示する」というのは、Reactアプリで非常によく出てくる要求。JSXの中で条件分岐する主な方法が2つある。

**三項演算子** — 「条件によって、2択のどちらかを表示する」時:

```tsx
{isLoggedIn ? <p>ようこそ</p> : <p>ログインしてください</p>}
```

**`&&`(論理AND)演算子** — 「条件を満たす時だけ表示し、満たさない時は何も表示しない」時:

```tsx
{isLoading && <p>読み込み中...</p>}
```

`&&`の仕組みは、JSの評価ルールを応用してる:`条件 && 表示したいもの`と書くと、条件が`true`の場合だけ右側(表示したいもの)が評価されて画面に出る。条件が`false`の場合は、そこで評価が止まって何も表示されない(`false`自体はReactが「何もない」として扱ってくれる)。

三項演算子との使い分け:「両方のパターンを出し分けたい→三項演算子」「片方だけ、あるかないか→`&&`」というのが基本の目安。

## 実際のプロトタイプでの例

Train_Proto-Typeの`App.jsx`から、`&&`を使ったシンプルな例:

```jsx
{showSpeed && (
  <div className="speed-indicator">
    {/* 速度表示のUI */}
  </div>
)}
```

これは「`showSpeed`(速度表示をオンにする設定)が`true`の時だけ、速度インジケーターを表示する」という処理。

Cake-Gameの`App.tsx`では、`&&`が複数条件を組み合わせる形でも使われてる:

```tsx
activeOrder.recipePieces !== undefined &&
!recipeMatched &&
// ...
```

これは前に学んだ「関係演算子(`!==`)」「否定(`!`)」と組み合わせて、「レシピの指定があり、かつ、まだレシピが一致していない場合」という、複数条件をまとめて1つの真偽値にする書き方。JSXの表示条件だけでなく、「複数の条件が全部揃ってるか」を判定する場面全般で`&&`は使われる、ということも覚えておくといい。

## コラム:Java・Railsとの対応

### Java

```java
if (isLoggedIn) {
    // ようこそ表示
} else {
    // ログイン画面表示
}
```

Javaの`if`/`else`の考え方自体は同じだけど、JavaのGUIには「UIをその場で`if`文の中に直接書く」という発想があまりない(先にコンポーネントを作っておいて、`.setVisible(true/false)`のように後から表示・非表示を切り替えるスタイルが主流)。JSXは「今表示すべきUIを、式として毎回計算し直す」という考え方なので、`if`と`&&`の使われ方の感覚はJavaと少し違う。

### Rails

ERBでも普通に`if`/三項演算子が使える:

```erb
<% if is_logged_in %>
  <p>ようこそ</p>
<% else %>
  <p>ログインしてください</p>
<% end %>
```

発想はJSXの三項演算子と同じだけど、ERBは`<% %>`(処理だけ、画面に出さない)と`<%= %>`(値を画面に出す)を使い分ける必要がある。JSXは`{}`の中に書いた式の結果がそのまま表示される、という一本のルールだけで済むので、その点はJSXの方がシンプル。

## 演習

`score`(数値)というPropsを受け取るコンポーネントを作成してください。`score`が`100`以上なら`「満点です!」`という`<p>`を、そうでなければ`「score`点でした」`という`<p>`を、三項演算子を使って出し分けてください。さらに、`score`が`0`の場合だけ追加で`「頑張りましょう」`という`<p>`も、`&&`を使って表示してください。
