## 説明

配列のデータを、複数のUI要素として一覧表示したい時は、1章で学んだ`.map()`をJSXの中で使う。

```tsx
const fruits = ["りんご", "バナナ", "みかん"];

function FruitList() {
  return (
    <ul>
      {fruits.map((fruit) => (
        <li key={fruit}>{fruit}</li>
      ))}
    </ul>
  );
}
```

ここで必須になるのが**`key`**という特別なProps。配列から複数の要素を作る時、Reactは`key`を手がかりにして「どの要素が、前回と同じものか」を判別してる。`key`がないと動作はするものの、コンソールに警告が出て、特定の操作(並び替え、途中の要素の削除など)で表示がおかしくなるバグの原因になる。

`key`に指定する値の鉄則:**その配列の中で、絶対に重複しない、一意な値**を使うこと。多くの場合、データが持ってる`id`のようなものを使うのが望ましい。配列のインデックス番号(0, 1, 2...)を`key`に使うのは、要素の並び替えや削除が起きると本来の意図とズレてしまうことがあるため、可能な限り避けた方がいいとされている。

## 実際のプロトタイプでの例

Cake-Gameの`components/CakeSelector.tsx`(2-1で最初に見た例)から:

```tsx
{cakes.map((cake) => {
  const isUnlocked = unlockedCakeIds.includes(cake.id)
  const canBuy = money >= cake.price

  return (
    <article
      key={cake.id}
      className={cake.id === activeCakeId ? 'cake-option is-active' : 'cake-option'}
    >
      {/* ... */}
    </article>
  )
})}
```

`key={cake.id}`と、ケーキそれぞれが持つ`id`(1章の`CakeDefinition`interfaceで定義されてた、一意な識別子)をそのまま`key`として使ってる。ケーキの表示順が変わったり、途中に新しいケーキが追加されたりしても、Reactは`id`を手がかりに「これは同じケーキの表示を継続してる」と正しく認識できる。

`.map()`の中で`return`を使って複数行の処理をしてから、最後にJSXを返してるのも実践的なパターン(`isUnlocked`, `canBuy`という判定結果を、先に計算してからJSXの中で使ってる)。

## コラム:Java・Railsとの対応

### Java

```java
for (Cake cake : cakes) {
    // UIコンポーネントを1個ずつ作って、リストに追加していくイメージ
}
```

Javaの拡張for文でリストを1個ずつ処理する発想は`.map()`と近いけど、Javaには「`key`のような、要素の同一性を追跡する仕組み」を明示的に要求される場面はあまりない。これはReact特有の、「画面を毎回まるごと計算し直すが、実際の書き換えは最小限に抑えたい」という設計思想から来てる要求。

### Rails

ERBでの繰り返し表示:

```erb
<% @cakes.each do |cake| %>
  <li><%= cake.name %></li>
<% end %>
```

`.each`で1個ずつ処理する発想は`.map()`と同じだけど、Railsには`key`のような概念が存在しない。理由は、Railsは基本的に「サーバー側で全部のHTMLを作り直して、まるごと送り返す」仕組みだから、Reactのように「画面の一部分だけを効率的に書き換える」ための目印が要らない。ただしTurbo(Hotwireの一部)を使うと、部分的な差し替えが必要になる場面が出てきて、そこでは`id`をキーにした要素の識別が重要になってくる。これはReactの`key`が果たしてる役割と、目的としてはかなり近い。

## 一緒にやってみる

演習に入る前に、配列から一覧を作る形を書いてみよう。
プロトタイプの`cakes.map((cake) => ...)`と同じく、`key`に**idを使う**形:

```tsx
<ul>
  {cakes.map((cake) => (
    <li key={cake.id}>{cake.name}</li>
  ))}
</ul>
```

このコードを、**コピペせずに自分の手で入力してみてほしい**。書けたら、
配列に要素を1つ足して、表示が増えることを確かめてみよう。

<TryIt />

書き方の型を整理すると:

```
{配列.map((要素) => (
  <タグ key={要素.id}>{中身}</タグ>
))}
```

- `.map()`で「配列の各要素 → 1つのJSX」に変換する
- `key`は、Reactがどの要素がどれかを見分けるための目印
- **`key`にはデータが持つ一意な値(idなど)を使う**。並び替えや削除で表示が壊れなくなる

演習では、この形で`students`から`<li>`の一覧を作ることになる。

## 演習

`students`という配列(`[{ id: "s1", name: "のりまき" }, { id: "s2", name: "しばまき" }]`)を受け取り、それぞれの名前を`<li>`として一覧表示するコンポーネントを作成してください。`key`に何を使うべきかも意識して書くこと。
