## この演習について

1章・2章に続き、今回は「配列操作」や「状態更新」まわりの、実践的なバグを扱う。以下の3つのコード例、それぞれ何が問題か指摘し、修正してください。

---

### コード例1

```ts
function sortBySpeedDescending(trains: Train[]): Train[] {
  return trains.sort((a, b) => b.speed - a.speed);
}
```

**ヒント**:3-5(`.find()`/`.some()`/`.sort()`)で学んだ内容に関係がある。

<details>
<summary>解答を見る</summary>

**問題**:`.sort()`は**元の配列を直接書き換えてしまう(破壊的メソッド)**。この関数は「新しい並び替え済みの配列を返す」ように見えるが、実際には引数として渡された`trains`配列そのものを変更してしまっている。呼び出し元が「元の順序のままの`trains`」を別の場所で使うつもりだった場合、意図せずデータが変わってしまうバグになる。

**修正例**:

```ts
function sortBySpeedDescending(trains: Train[]): Train[] {
  return [...trains].sort((a, b) => b.speed - a.speed);
}
```

スプレッド構文で配列をコピーしてから`.sort()`することで、元の配列に影響を与えないようにする。

</details>

### コード例2

```ts
function getTrainSpeed(trains: Train[], name: string): number {
  const train = trains.find((t) => t.name === name);
  return train.speed;
}
```

**ヒント**:1-05(オプショナルチェイニング)、3-5(`.find()`)で学んだ内容に関係がある。

<details>
<summary>解答を見る</summary>

**問題**:`.find()`は、条件に合う要素が見つからない場合`undefined`を返す。この関数は、`train`が`undefined`になる可能性を一切考慮せず`train.speed`にアクセスしてしまっている。指定した`name`の電車が存在しない場合、実行時エラーになる。

**修正例**:

```ts
function getTrainSpeed(trains: Train[], name: string): number | undefined {
  const train = trains.find((t) => t.name === name);
  return train?.speed;
}
```

`?.`を使い、`train`が`undefined`の場合は`undefined`を返すようにする。あわせて、戻り値の型も`number`ではなく`number | undefined`に変える必要がある(「見つからない可能性がある」ことを、型の上でも正直に表現する)。

</details>

### コード例3

```tsx
function DispatchPanel() {
  const [rails, setRails] = useState<Rail[]>([...]);

  const toggleRail = (railId: string) => {
    setRails(
      rails.map((rail) =>
        rail.id === railId ? { ...rail, isPlaced: !rail.isPlaced } : rail
      )
    );
  };

  const handleRapidClicks = () => {
    toggleRail("r1");
    toggleRail("r1"); // 連続で呼び出す
  };

  return <button onClick={handleRapidClicks}>連続切り替え</button>;
}
```

**ヒント**:3-4(クリックでレールを選択・配置)、2-4(useStateの基礎)で学んだ内容に関係がある。

<details>
<summary>解答を見る</summary>

**問題**:`toggleRail`が、更新のたびに**コンポーネント内の`rails`という古い値**を直接参照してしまっている(関数型更新になっていない)。`handleRapidClicks`のように、同じ更新関数を連続で呼び出すと、2回目の`toggleRail("r1")`も**1回目の呼び出し前の`rails`**を元に計算されてしまい、結果的に「2回反転させたつもりが、1回しか反映されない」というバグが起きる。

**修正例**:

```tsx
const toggleRail = (railId: string) => {
  setRails((previousRails) =>
    previousRails.map((rail) =>
      rail.id === railId ? { ...rail, isPlaced: !rail.isPlaced } : rail
    )
  );
};
```

`setRails((previousRails) => ...)`のように関数型更新にすることで、**常に直前の最新の状態**を元に計算されるようになり、連続呼び出しでも正しく動作する。

</details>

## まとめ

今回の3つの問題(`.sort()`の破壊性、`.find()`の`undefined`考慮漏れ、関数型更新の欠如)は、いずれも**「一見正しく動きそうだけど、特定の状況でだけ壊れる」**という、実践でありがちなバグのパターン。特に3つ目は、連続クリックのような「タイミングが絡む」バグで、テストや軽い動作確認だけでは見つけにくい部類。AIが生成したコードのレビューでも、こうした「普段は気づかれにくい落とし穴」を意識して見る習慣が大事になる。
