## この演習について

3章は、ここまでの1章(JS/TS基礎)・2章(React基礎)で学んだ知識を総動員して、「電車の運行管理パネル」という1つのミニアプリを、レッスンを通して少しずつ組み上げていく。今回はその第一歩、土台となるデータ構造とstateを設計する。

## 説明

まず、扱うデータの形を決める。1章で学んだinterfaceとunion typeを使う:

```ts
interface Train {
  id: string
  name: string
  speed: number
  delayMinutes: number
}

interface Rail {
  id: string
  type: "fast" | "normal"
  isPlaced: boolean
}
```

`Train`は前に総合演習でも扱った形と似てる。`Rail`には`isPlaced`(配置済みかどうか)という真偽値を新しく追加してる。これは後のレッスン(クリックで配置)で使う。

このデータを、2章で学んだ`useState`で管理する:

```tsx
function DispatchPanel() {
  const [trains, setTrains] = useState<Train[]>([
    { id: "t1", name: "のぞみ1号", speed: 300, delayMinutes: 0 },
    { id: "t2", name: "ひかり5号", speed: 250, delayMinutes: 3 },
  ]);

  const [rails, setRails] = useState<Rail[]>([
    { id: "r1", type: "fast", isPlaced: false },
    { id: "r2", type: "normal", isPlaced: true },
  ]);

  return (
    <div>
      {/* ここに、後のレッスンで作っていく画面が入る */}
    </div>
  );
}
```

1つのコンポーネントの中に、複数の独立したstateを持たせる、という2-4(useStateの基礎)で扱ったパターンをそのまま踏襲してる。`trains`と`rails`は、それぞれ別の関心事(電車の運行状況、レールの配置状況)を表してるので、1つの巨大なstateにまとめず分けている。

## 実際のプロトタイプとの関連

このデータ構造は、前の総合演習(1-15, 2-10)ですでに扱った`Train`型・`Rail`型を土台にしてる。3章では、これらを1つの画面の中で連携させて動かす、というのが今までとの違い。1章・2章では「機能ごとの断片」を作ってきたけど、3章では「1つのアプリとして最初から最後まで責任を持つ」経験をしてもらう。

## 一緒にやってみる

演習に入る前に、「型を決めてから、その型のstateを持つ」という順番を1回なぞっておこう。
題材は駅の一覧にしてみる:

```tsx
interface Station {
  id: string;
  name: string;
}

const [stations, setStations] = useState<Station[]>([]);
```

このコードを、**コピペせずに自分の手で入力してみてほしい**。書けたら、
初期値に駅を1つ入れて、画面に件数が出ることを確かめてみよう。

<TryIt />

進め方の型を整理すると:

1. **先に`interface`で「1件分の形」を決める**
2. そのうえで`useState<型[]>([])`と書き、配列のstateにする
3. 表示は`stations.length`や`.map()`で組み立てる

- 型を先に決めておくと、`useState`の`<>`に何を書くかで迷わなくなる
- 独立した情報は、1つのstateにまとめず**別々の`useState`**に分けてよい

演習では、この順番で`Train`・`Rail`の型と、2つのstateを作ることになる。
