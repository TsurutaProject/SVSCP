## この演習について

1〜3章に続き、今回は非同期処理・Server Actionsまわりの、実践的なバグを扱う。以下の3つのコード例、それぞれ何が問題か指摘し、修正してください。

---

### コード例1

```ts
async function getCakeRanking() {
  const response = fetch("/api/cakes/popularity");
  const data = response.json();
  return data;
}
```

**ヒント**:4-3(Promiseとasync/await)で学んだ内容に関係がある。

<details>
<summary>解答を見る</summary>

**問題**:`fetch(...)`と`response.json()`、**両方とも`await`が抜けている**。`fetch`はPromiseを返す関数なので、`await`なしでは`response`には「まだ結果が返ってきていない、Promiseそのもの」が入ってしまう。`.json()`も同様に非同期の処理なので、これも`await`が必要。

**修正例**:

```ts
async function getCakeRanking() {
  const response = await fetch("/api/cakes/popularity");
  const data = await response.json();
  return data;
}
```

`async`関数の中で非同期処理を呼ぶ場合、**呼び出しのたびに`await`をつけ忘れていないか**を必ず確認する習慣が大事。

</details>

### コード例2

```ts
"use server";

export async function voteForCake(cakeKind: string) {
  await db.incrementVote(cakeKind);
  revalidatePath("/cakes/ranking");
}
```

**ヒント**:4-7(API Routes / Server Actions)、`actions.ts`の実例で学んだ内容に関係がある。

<details>
<summary>解答を見る</summary>

**問題**:`cakeKind`が、本当に`"shortcake"`や`"chocolate"`のような正しい値かどうかを**一切チェックせず**、そのままデータベースの処理に渡してしまっている。Server Actionsはブラウザ側のコードから直接呼び出せる分、**悪意のある、または誤ったデータが送られてくる可能性を常に考慮する必要がある**。

**修正例**:

```ts
"use server";

const VALID_CAKE_KINDS = ["shortcake", "chocolate"];

export async function voteForCake(cakeKind: string) {
  if (!VALID_CAKE_KINDS.includes(cakeKind)) {
    return;
  }

  await db.incrementVote(cakeKind);
  revalidatePath("/cakes/ranking");
}
```

`actions.ts`の`updateExerciseStatus`が`EXERCISE_STATUSES.includes(status as ExerciseStatus)`で行っていたのと同じ、**早期リターンによるバリデーション**を必ず入れる。Server Actionsは「関数を呼んでるだけ」のように見えても、実態はネットワーク越しに呼ばれる処理であり、**フォームや外部からの入力と同じように、信頼できないデータとして扱う**必要がある。

</details>

### コード例3

```ts
export async function GET() {
  const rankings = await getRankingsFromDatabase();
  return Response.json(rankings);
}
```

このAPI Routeを呼び出す側:

```tsx
async function RankingPage() {
  const response = await fetch("/api/cakes/popularity");
  const data = await response.json();

  return (
    <ul>
      {data.map((item) => (
        <li key={item.cakeKind}>{item.cakeKind}: {item.votes}票</li>
      ))}
    </ul>
  );
}
```

**ヒント**:4-4(try/catchとエラーハンドリング)で学んだ内容に関係がある。

<details>
<summary>解答を見る</summary>

**問題**:`getRankingsFromDatabase()`や`fetch`が失敗する可能性が、**どちらのコードでも一切考慮されていない**。データベースへの問い合わせが失敗したり、ネットワークエラーが起きたりした場合、これらの関数はエラーを投げる可能性があるが、それを受け止める`try`/`catch`がどこにもない。エラーが発生すると、ユーザーには真っ白な画面やクラッシュとして表示されてしまう。

**修正例**(呼び出し側):

```tsx
async function RankingPage() {
  try {
    const response = await fetch("/api/cakes/popularity");
    const data = await response.json();

    return (
      <ul>
        {data.map((item) => (
          <li key={item.cakeKind}>{item.cakeKind}: {item.votes}票</li>
        ))}
      </ul>
    );
  } catch {
    return <p>ランキングを取得できませんでした。</p>;
  }
}
```

外部との通信が絡む処理(`fetch`やデータベース呼び出し)は、**「失敗する可能性がある」ことを前提に、必ず`try`/`catch`で守る**。総合演習(4-8)でも同じ対応をしていたはず。

</details>

## まとめ

今回の3つの問題(`await`の付け忘れ、入力値の未検証、エラーハンドリングの欠如)は、**非同期処理・サーバーとの通信が絡むコードで特に見落とされやすいパターン**。AIが生成したコードは、「一番シンプルな成功パターン」だけを書いて、失敗時の処理や入力検証を省略しがちなので、レビューの際は「これ、失敗したらどうなる?」「この値、本当に正しいと保証されてる?」と自問する習慣をつけるといい。
